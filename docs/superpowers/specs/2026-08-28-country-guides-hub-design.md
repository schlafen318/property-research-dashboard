# Country Guides Hub Design

## Objective

Create a permanent `/countries/` discovery page that helps foreign buyers choose the correct research path: an acquisition guide, a retirement guide, or a destination dossier. The page must improve internal linking and search discoverability without duplicating the country guides or becoming a generic marketing landing page.

## Audience and primary decisions

The page serves readers who know the country they are considering but have not yet chosen the right guide or destination. It must answer three questions immediately:

1. Which country-level guide covers buying mechanics and risks?
2. Is a retirement-specific guide available?
3. Which destination dossiers provide local market evidence?

The Atlas rankings and retirement calculator remain separate products. The hub links to them as decision tools rather than reproducing their interfaces.

## Information architecture

The page uses the established Global Home Atlas editorial shell and contains only distinct, useful sections:

1. A concise hero with the H1 `Country Property Guides for Foreign Buyers` and a factual description of the directory.
2. Two direct tool links: destination rankings and the retirement calculator.
3. A country directory containing every `COUNTRY_HUBS` entry exactly once.
4. A short explanation distinguishing acquisition guides, retirement guides, and destination dossiers.
5. A compact research-method link at the end.

Each country entry presents:

- the country name;
- one sentence derived from the existing country thesis;
- a clearly labelled acquisition-guide link;
- a retirement-guide link only when a published guide exists;
- links to every associated destination dossier.

Do not add empty states, `coming soon` labels, counts that become stale, decorative badges, duplicated summaries, or generic conversion prose.

## Data and rendering

The page is generated by `src/build_unified_app.py` from existing sources of truth:

- `COUNTRY_HUBS` supplies country names, acquisition-guide slugs, descriptions, and destination IDs.
- `COUNTRY_RETIREMENT_GUIDES` and existing guide metadata determine whether a published retirement guide exists and its URL.
- the destination dataset resolves destination names and dossier URLs.

The builder must not introduce a second country catalogue. New countries and destinations should appear automatically when their existing records are added.

The directory may include a small client-side text filter. Filtering is progressive enhancement: all country links remain present in the server-rendered HTML and usable without JavaScript.

## Navigation and internal linking

The global `Countries` navigation item must point to `/countries/`. Existing individual country URLs remain unchanged.

The hub links outward to:

- all published acquisition guides;
- all published retirement guides represented in country data;
- all destination dossiers associated with those countries;
- `/country-comparison/` for cross-country comparison;
- `/retirement-destinations-ranked-by-cost/` and `/retirement-abroad-calculator/` as the two proprietary tools;
- `/methodology/` for the scoring framework.

No page should be linked with ambiguous text such as `Learn more` or `Read guide` without the guide type.

## Search and structured data

The page must include:

- a unique title and meta description aligned with country property guides for foreign buyers;
- canonical URL `https://globalhomeatlas.com/countries/`;
- a visible breadcrumb and `BreadcrumbList` structured data;
- `CollectionPage` and `ItemList` structured data whose items correspond to the acquisition-guide directory;
- sitemap inclusion;
- one H1 and a logical heading hierarchy.

The introduction must be concise and useful. Keyword repetition, synthetic destination counts, and generic SEO prose are prohibited.

## Presentation and interaction

Use the current premium editorial design language: warm paper background, dark green ink, restrained brass accent, serif display headings, and readable sans-serif utility text. The country directory should read as an editorial index, not a dashboard or a grid of promotional cards.

Desktop rows may use columns for country, guide types, and destinations. On narrow screens, each row stacks while keeping link labels and tap targets clear. The optional text filter must have an explicit label, support keyboard input, and announce the number of visible countries.

Track only useful engagement events:

- acquisition-guide clicks;
- retirement-guide clicks;
- destination-dossier clicks;
- rankings and calculator clicks;
- country filter use.

## Verification

Automated tests must confirm:

- `/countries/index.html` is generated;
- every `COUNTRY_HUBS` entry appears once;
- acquisition, retirement, and destination links resolve to generated pages;
- the title, canonical, breadcrumb, structured data, and sitemap entry are present;
- the global navigation points to `/countries/`;
- no `coming soon` or stale destination-count copy is emitted.

The final build must pass the full existing test suite and `git diff --check`. Visual verification must cover desktop and mobile layouts, filter behaviour, keyboard access, overflow, console errors, and representative links.
